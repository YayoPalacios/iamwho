# Evaluate OIDC subject and audience conditions statically

iamwho is not a policy simulator and does not otherwise evaluate `Condition` blocks, but web-identity trust is only meaningful through its subject conditions, so for GitHub Actions trusts we evaluate `sub` and `aud` — and only those — statically, honoring operator semantics: `StringEquals` values are literal (no wildcard expansion), `StringLike` values are case-sensitive glob patterns, condition key names match case-insensitively, any broad value in a multi-value list makes the whole condition broad, and `aud` is assessed independently of `sub`. For GitHub, `aud` never changes the `sub` verdict, because any workflow can mint a `sts.amazonaws.com` token; that rule is GitHub-specific (for Cognito, `aud` is the identifying condition). When the subject condition itself cannot be evaluated — a provider without subject rules, an unrecognised operator, a custom claim template — it is reported as not evaluated rather than guessed at or scored reassuringly. An evaluated subject verdict keeps its severity even when the statement carries other condition keys; those keys are listed, not evaluated. Checking that a provider's identifying key is *present* (GitHub/EKS/generic `sub`, Cognito `aud`) is not value evaluation and applies to every provider: its absence means any token from that IdP — or, for shared IdPs like GitHub and Cognito, any tenant of it — can assume the role. Across multiple statements the worst one wins, and unevaluated keys or `Deny` statements are listed but never credited as narrowing. Results are still *potential* reach, not proven authorization.

## Considered Options

- **Key-presence only** (prior behaviour): treated `sub: "repo:*"` as restricted, so it could not tell an all-of-GitHub trust from a single-branch trust.
- **General condition evaluation**: would turn iamwho into a partial policy simulator, which is explicitly out of scope.
- **Per-provider evaluation in one step** (GitHub, EKS, Cognito): deferred; each provider has its own identifying claims and needs its own fixtures.
